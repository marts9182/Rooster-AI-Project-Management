## Decision

Decision: GO — proceed with Path C (CLI subprocess) per spec §1.

Notes / deviations from the plan's vetted skeleton, discovered during the
spike — these must be reflected in the Phase 2 implementation:

1. Two flags are needed, not one. `--session-id <uuid>` creates a NEW
   session and errors with "already in use" if reused. To send a second
   turn into the same conversation, use `--resume <uuid>`. The spike's
   first run with `--session-id` on both turns showed turn 2 exiting 1
   with `Error: Session ID ... is already in use.`
2. On Windows the `claude` binary is a `.cmd` / `.ps1` shim, so
   `child_process.spawn('claude', ...)` without `shell: true` fails with
   `ENOENT`. Production code must either set `shell: true` or resolve
   the absolute path to `claude.cmd` first (the latter avoids the Node
   DEP0190 deprecation warning about unescaped shell arguments).
3. Streaming + tool_use markers require `--output-format stream-json
   --verbose` (verbose is mandatory when combining stream-json with
   `--print`). `--include-partial-messages` gives the finest-grained
   `content_block_delta` events. Without these, stdout arrives as a
   single chunk and tool calls are invisible.
4. Headless mode auto-skips the workspace trust dialog when stdout is
   not a TTY (documented behavior of `--print`); no `--permission-mode`
   or `--dangerously-skip-permissions` flag was needed for the Read
   tool used in this spike. Spec §8 risk (d) was about permission
   prompts blocking — confirmed they do NOT block for Read in `--print`
   mode under the default permission policy. Other tools (Edit, Bash,
   Write) may still prompt; revisit in Phase 2 if the chat surface
   needs to exercise those.
5. First-byte latency was excellent on both turns (~0.9s cold,
   ~1.4s warm) — well inside the spec's UX budget. Worth measuring
   again under load in Phase 2.
